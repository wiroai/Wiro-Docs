# Wiro API Documentation Project

**IMPORTANT: When any API docs content is changed in `index.html`, the corresponding Markdown file in `markdown/{slug}.md` (same name as the section hash, e.g. `#/run-a-model` → `markdown/run-a-model.md`) AND `markdown/full-documentation.md` MUST also be updated to match. Markdown files must stay in sync with the HTML content at all times.**

This is an open-source, static API documentation site for Wiro (wiro.ai). The primary goal is **API documentation content**, not the docs system itself.

## Architecture

- Pure HTML/CSS/JS — no build tools, no frameworks
- Single `index.html` with all doc sections inline (LLM-friendly, viewable in source)
- `css/docs.css` for all styling
- `js/app.js` for navigation, dark mode, code panel (ES module)
- `js/helpers.js` for API-dependent features (model browser)
- CDN dependencies only: Google Fonts, LineIcons, Shiki (lazy-loaded)
- Content must always be static HTML — never load content via JS fetch

## Commit & Push Rules (CRITICAL)

**NEVER commit or push without explicit user approval.**

### Two Categories of Changes — Always Separate

1. **API docs content** (`[docs]` prefix): Changes to documentation text, code examples, API descriptions, parameter tables, section content inside `index.html`, and `llms.txt`.

2. **Docs system** (`[system]` prefix): Changes to CSS, JS, HTML structure, layout, navigation, tooling, config files.

These MUST be committed separately. Never mix content and system changes in one commit.

### Commit Message Format

```
[docs] Add webhook callback documentation to Run section
[docs] Fix incorrect parameter type for Task/Detail endpoint
[system] Fix mobile nav overlay z-index
[system] Add Shiki syntax highlighting for code panel
```

### Rules

- Write clear, human-authored commit messages — no AI/tool mentions
- No "Generated by", "Created by Cursor", or similar attributions
- Describe the WHY, not the HOW
- API docs commits will be filtered for changelogs — make them descriptive
- Always ask user before committing or pushing

## Content Guidelines

- All API content must be accurate and match the live Wiro API
- Code examples in 9 languages: curl, Python, Node.js, PHP, C#, Go, Swift, Kotlin, Dart
- Internal docs links use `#/slug` format
- External Wiro links use full `https://wiro.ai/...` URLs
- `pexit` is the primary success indicator, not `outputs`
- LLM models return responses in `debugoutput`, not `outputs`

## LLM Friendliness

- All content visible in view-source (no JS-loaded content)
- Semantic HTML structure
- `llms.txt` kept in sync with HTML content
- Minimal JS — only for UI interactions, not content delivery
